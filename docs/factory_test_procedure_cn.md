# T5 E-Paper Basic 工程测试流程

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 适用产品 | LILYGO T5 E-Paper Basic |
| 测试固件 | `examples/factory_test/main.cpp` |
| PlatformIO 环境 | `T5_E_PAPER_BASIC` |
| 测试内容 | EPD 屏幕、XL9555、SD 卡、Wi-Fi、BTN0～BTN4、BOOT |
| 串口波特率 | 115200 |
| 文档版本 | V1.0 |
| 更新日期 | 2026-07-23 |

## 2. 测试目的

本流程用于产品装配完成后的工程验证和出厂检验，确认以下功能正常：

1. 电子纸能够正常初始化、完整刷新并正确显示黑、白和灰阶。
2. XL9555 扩展 IO 能够正常通信。
3. SD 卡能够检测、挂载、读取、写入和删除测试文件。
4. Wi-Fi 能够扫描附近网络，并能连接指定测试热点。
5. BTN0～BTN4 和 BOOT 按键能够正确识别按下及松开状态。

## 3. 测试设备与环境

### 3.1 必备设备

- 待测 T5 E-Paper Basic 整机。
- 支持数据传输的 USB-C 线。
- 可用的 USB 串口或原生 USB 接口。
- FAT32 格式的 SD 卡，建议容量 8 GB～32 GB。
- 可提供 2.4 GHz Wi-Fi 的路由器或手机热点。
- 安装 PlatformIO 的电脑，或安装 Python 和 `esptool.py` 的生产烧录电脑。

### 3.2 Wi-Fi 测试热点

固件会按照下列顺序尝试连接测试热点：

| 优先级 | SSID | 密码 |
| --- | --- | --- |
| 1 | `LilyGo-AABB` | `xinyuandianzi` |
| 2 | `xinyuandianzi` | `AA15994823428` |

为了完成完整的 Wi-Fi 连接测试，测试现场至少开启其中一个热点。热点必须工作在 ESP32-S3 支持的 2.4 GHz 频段。

## 4. 固件编译与烧录

### 4.1 PlatformIO 编译

在工程根目录执行：

```powershell
pio run -e T5_E_PAPER_BASIC
```

编译成功时终端应显示：

```text
[SUCCESS]
```

### 4.2 PlatformIO 直接烧录

连接待测设备后执行：

```powershell
pio run -e T5_E_PAPER_BASIC -t upload
```

如果无法自动进入下载模式：

1. 按住 BOOT。
2. 短按 RESET。
3. 松开 BOOT。
4. 重新执行烧录命令。

### 4.3 使用合并固件烧录

工程构建脚本会生成可从 `0x0` 地址烧录的 ESP32-S3 合并固件。生产烧录命令示例：

```powershell
python script\esptool.py --chip esp32s3 --port COMx --baud 921600 write_flash 0x0 firmware\firmware_T5_E_PAPER_BASIC_YYYYMMDD.bin
```

将 `COMx` 替换为实际串口，将固件名替换为当前发布版本。烧录完成后按 RESET，或重新上电。

### 4.4 打开串口日志

```powershell
pio device monitor --baud 115200
```

串口日志可辅助判断故障，但最终必须同时检查实机画面和操作结果。

## 5. 测试前检查

1. 检查屏幕排线、SD 卡座、USB 接口和所有按键是否装配到位。
2. 检查屏幕表面是否破裂、进液、受压或存在明显外观损伤。
3. 首次上电前不插入 SD 卡，用于验证“未发现 SD 卡”状态。
4. 开启至少一个指定 Wi-Fi 测试热点。
5. 确认测试热点允许新设备接入并能够分配 DHCP 地址。

## 6. 标准测试流程

### 6.1 上电和屏幕测试

1. 给设备上电或按 RESET。
2. 等待屏幕完成首次刷新。
3. 检查屏幕测试画面，包括：
   - 标题和屏幕分辨率。
   - 16 级灰阶。
   - 棋盘格。
   - 几何图形。
   - 线条、像素和对比度区域。
4. 测试画面完成刷新后应保持约 3 秒。
5. 3 秒后设备自动进入出厂测试主页面。

通过标准：

- 屏幕方向正确，画面尺寸为 540 × 960。
- 四边和四角内容完整，无明显裁切或错位。
- 黑色、白色和灰阶能够区分。
- 无持续横纹、花屏、大面积缺线、固定黑块或无法刷新的区域。
- 主页面顶部“屏幕”状态显示 `PASS`。

### 6.2 XL9555 扩展 IO 测试

进入主页面后检查“按键 / IO”状态。

通过标准：

- 状态显示 `PASS`。
- 串口输出包含：

```text
[IO] XL9555 ready
```

失败表现：

- 页面显示 `CHECK`。
- 串口输出 `[IO] XL9555 not found`。
- BTN0～BTN4 无法响应。

### 6.3 未插卡状态测试

在未插入 SD 卡时检查 SD 测试区域。

通过标准：

- 页面显示“未发现 SD 卡”或 `NO CARD`。
- 不应错误显示 SD 测试 `PASS`。

### 6.4 SD 卡测试

1. 在主页面稳定后插入 FAT32 格式 SD 卡。
2. 等待设备自动检测并完成测试。
3. 检查 SD 区域显示内容：
   - 卡类型。
   - 卡容量。
   - 已用空间和总空间。
   - 根目录数量和文件数量。
   - 挂载结果。
   - 读写结果。
4. 检查状态标识是否显示黑底白字 `PASS`。
5. 拔出 SD 卡，确认页面恢复为未插卡状态。
6. 再次插入 SD 卡，确认能够重新测试并再次通过。

固件测试过程：

1. 根据卡检测引脚判断是否插卡。
2. 最多尝试挂载 3 次。
3. 在根目录创建临时测试文件。
4. 写入固定测试内容。
5. 重新打开文件并校验内容。
6. 删除临时测试文件。

通过标准：

- 卡类型和容量与实际 SD 卡基本一致。
- 页面显示“挂载：PASS”和“读写：PASS”。
- 顶部状态显示 `PASS`。
- 测试完成后 SD 卡根目录中不存在 `.lilygo_factory_test.tmp`。
- 拔插 SD 卡能够被正确识别。

### 6.5 Wi-Fi 扫描测试

1. 进入主页面后等待 Wi-Fi 扫描完成。
2. 检查附近网络列表。
3. 对比同一位置的手机或电脑扫描结果。
4. 检查网络是否按照 RSSI 从强到弱排列。
5. 检查每一行是否显示 SSID、RSSI 和信号强度图标。

通过标准：

- 能够扫描到测试现场附近的 2.4 GHz Wi-Fi。
- 列表中 RSSI 数值从大到小排列，例如 `-45 dBm` 应排在 `-70 dBm` 前。
- SSID、RSSI 和信号图标显示清楚。
- Wi-Fi 区域为纯白背景，不应出现由灰色背景产生的密集抖动点。

如果附近没有指定热点，页面允许显示“仅显示扫描结果”。该状态只能证明扫描功能正常，不能代替指定热点连接测试。

### 6.6 Wi-Fi 连接测试

1. 确认 `LilyGo-AABB` 或 `xinyuandianzi` 热点已开启。
2. 等待扫描完成。
3. 设备会优先连接 `LilyGo-AABB`；连接失败或未发现时再尝试 `xinyuandianzi`。
4. 检查 Wi-Fi 区域顶部状态。
5. 连接成功后检查：
   - 已连接 SSID。
   - DHCP 分配的 IP 地址。
   - RSSI 数值。
   - 信号强度图标。

通过标准：

- 页面显示“已连接”。
- SSID 与实际测试热点一致。
- IP 地址不是 `0.0.0.0`。
- RSSI 数值有效，通常应在 `-30 dBm`～`-90 dBm` 范围内。
- 串口输出包含：

```text
[WiFi] connected: <SSID>, IP=<IP>, RSSI=<RSSI> dBm
```

### 6.7 按键测试

逐个测试 BTN0、BTN1、BTN2、BTN3、BTN4 和 BOOT。每个按键必须至少完整按下、松开一次，不允许同时按多个按键。

| 页面位置 | 按键 | 硬件输入 |
| --- | --- | --- |
| 左侧上方 | BTN2 | XL9555 P02 |
| 右侧上方 | BTN4 | XL9555 P04 |
| 左侧中间 | BTN1 | XL9555 P01 |
| 右侧中间 | BTN3 | XL9555 P03 |
| 左侧下方 | BTN0 | XL9555 P00 |
| 右侧下方 | BOOT | ESP32-S3 GPIO0 |

每个按键的操作步骤：

1. 未按按键时，确认按键 UI 为纯白背景、纯黑字体，并显示 `UP`。
2. 按住实体按键。
3. 确认对应 UI 快速变为纯黑背景、纯白字体，并显示 `DOWN`。
4. 松开实体按键。
5. 确认对应 UI 快速恢复为纯白背景、纯黑字体，并显示 `UP`。
6. 检查其他按键 UI 不应同时改变。

串口参考输出：

```text
[KEY] BTN0 -> DOWN
[KEY] BTN0 -> UP
[KEY] BOOT -> DOWN
[KEY] BOOT -> UP
```

通过标准：

- 六个按键均能独立识别按下和松开。
- 页面标签与实际按键一致。
- 无长时间无响应、卡键、误触发或相邻按键联动。
- 按键 UI 只使用纯黑和纯白，不应出现灰色填充或密集灰点。

## 7. 整机通过标准

只有同时满足以下条件，整机测试结果才能判定为通过：

| 测试项目 | 通过条件 |
| --- | --- |
| EPD | 测试画面和主页面完整、方向正确、无明显显示故障 |
| XL9555 | 页面显示 `PASS`，BTN0～BTN4 正常 |
| SD 无卡检测 | 未插卡时正确显示无卡 |
| SD 挂载与读写 | 插卡后挂载、写入、读取、校验和删除全部通过 |
| Wi-Fi 扫描 | 能扫描附近网络并按 RSSI 排序 |
| Wi-Fi 连接 | 能连接至少一个指定测试热点并取得有效 IP |
| BTN0～BTN4 | 每个按键按下和松开均正确 |
| BOOT | GPIO0 按下和松开均正确 |

任意必测项目失败时，应将产品标记为不通过，并记录故障现象。

## 8. 常见故障处理

### 8.1 屏幕无显示

- 检查 USB 供电和固件是否正常启动。
- 检查屏幕排线和连接器。
- 查看串口是否输出 `[EPD] init failed`。
- 重新烧录确认固件完整。

### 8.2 屏幕出现横纹或花屏

- 重新上电，等待完整质量刷新结束。
- 检查屏幕排线是否插紧。
- 检查屏幕是否受压或损坏。
- 确认测试固件使用 4-bit 灰阶配置。

### 8.3 SD 卡无法通过

- 确认 SD 卡已完全插入。
- 更换已知正常的 FAT32 SD 卡。
- 检查卡座焊接和以下信号：
  - MOSI：GPIO38
  - SCK：GPIO39
  - MISO：GPIO40
  - CS：GPIO47
  - CARD_DET：XL9555 P05
- 查看串口中的 `[SD]` 日志。

### 8.4 Wi-Fi 扫描不到热点

- 确认热点为 2.4 GHz，不是仅 5 GHz。
- 缩短设备与热点之间的距离。
- 检查热点是否隐藏 SSID 或限制设备接入。
- 重启热点和待测设备后重新测试。

### 8.5 Wi-Fi 能扫描但无法连接

- 核对 SSID 和密码。
- 确认 DHCP 服务正常。
- 确认热点未开启 MAC 地址白名单或接入数量限制。
- 查看串口是否输出连接超时。

### 8.6 BTN0～BTN4 无响应

- 检查 XL9555 是否初始化成功。
- 检查 I2C SDA GPIO3、SCL GPIO2。
- 检查按键到 XL9555 P00～P04 的焊接。

### 8.7 BOOT 无响应

- 确认 BOOT 按键连接 GPIO0，按下时应为低电平。
- 检查 GPIO0 上拉和按键对地连接。
- BOOT 与 XL9555 GPIO1 中断无关。

## 10. 测试注意事项

- 电子纸刷新速度慢于 LCD，首次完整刷新期间不要断电。
- 按键采用局部快速刷新，连续测试时应等待当前按键状态显示完成。
- 不要在 SD 卡写入过程中拔卡。
- 不要使用损坏或供电不稳定的 USB 线进行测试。
- 测试完成后确认设备停留在主页面，且没有持续复位或异常日志。
